# 方法实验室

输入问题、选择方法、运行实验。网页调用现有 toolkit 与模型，显示实际输入、直接提问与处理后的回答，以及优化方法的搜索记录。“运行实验”的回答现场生成；“查看教学示意”使用明确标注的编写内容，不计入实测。

网页支持在本机运行模型，或通过 SSH 隧道连接远程推理服务。下面给出启动方式；模型、设备、精度和输出上限可通过后台参数设置，网页从接口读取当前配置。

## 常驻后台

常驻部署可以使用 macOS LaunchAgent 托管网页代理与 SSH 隧道，并在远程使用用户级 systemd 托管模型服务。以下管理命令以 `com.textbook-toolkit.lab` 为服务名；需先按自己的路径创建并安装对应服务定义。浏览器访问 `http://127.0.0.1:4173/`。

- 服务定义需填写当前机器的 Python、项目目录和 SSH 连接信息；机器专用配置不纳入源码仓库。
- macOS 安装位置：用户目录的 `Library/LaunchAgents/com.textbook-toolkit.lab.plist`。
- 日志：`private/service-logs/stdout.log` 和 `stderr.log`，不对网页开放。
- 远程可创建用户级 systemd `textbook-toolkit-lab.service`，启用开机启动和 linger 后，退出 SSH 不会结束服务。
- 模型只在远程后台启动时加载一次，首次启动或重启后请等页面显示“远程模型已就绪”。

macOS 管理命令（将 `USER_ID` 替换为 `id -u` 返回的数字）：

```bash
launchctl print gui/USER_ID/com.textbook-toolkit.lab
launchctl kickstart -k gui/USER_ID/com.textbook-toolkit.lab
```

第一条查看状态，第二条重启。重启会中断当前实验并清空内存记录，请在实验空闲时使用。暂停常驻服务：

```bash
launchctl bootout gui/USER_ID/com.textbook-toolkit.lab
```

重新启动：

```bash
launchctl bootstrap gui/USER_ID /path/to/Library/LaunchAgents/com.textbook-toolkit.lab.plist
```

关闭浏览器、终端或 Codex 不会停止服务；本机睡眠或退出登录时网页与隧道不可用，远程推理后台继续运行。重新登录会自动启动，唤醒后隧道会重新连接。网页与远程服务均只监听各自的回环地址。移动项目或更换 Python 环境时，需要同步更新服务定义并重新安装。

## 手动启动（调试用）

先暂停常驻服务，以免占用同一个端口；然后在 `textbook-toolkit/website` 目录中，用已安装 toolkit 依赖的 Python 环境运行：

```bash
python server.py
```

浏览器打开 `http://127.0.0.1:4173/`。手动不带参数启动时仍使用原本的本地 CPU 模式，默认模型路径为 `../.cache/SmolLM2-135M-Instruct`。可用 `--model /absolute/model/path --device cuda --dtype bfloat16` 指定兼容模型和设备；使用 `--upstream http://127.0.0.1:7417` 则只代理远程接口，不加载本机模型。隧道两端端口保持一致，以通过后端 Host 校验。服务仅监听本机；不要用静态文件服务器代替它。

使用已安装 toolkit 及优化依赖的 Python 环境。不需要前端安装或构建。

在远程项目根目录启动 GPU 模型服务：

```bash
python website/server.py --port 7417 --model /path/to/model \
  --model-name Mistral-7B-Instruct-v0.2 --device cuda --dtype bfloat16 \
  --location remote --max-new-tokens 128 --eval-batch-size 2
```

在本机建立隧道，并用另一个终端启动网页代理：

```bash
ssh -N -L 127.0.0.1:7417:127.0.0.1:7417 user@server
python website/server.py --port 4173 --upstream http://127.0.0.1:7417
```

三条命令需在各自终端持续运行；常驻部署时将同样的启动参数配置到系统服务。

## 实验流程

1. 选择已有方法，阅读三步原理说明。
2. 选择受限请求示例，查看攻击目标与预期边界；也可以填写自己的问题。优化方法额外填写期望的回答开头与尝试轮数。
3. 后台先生成直接提问的回答，再执行所选方法，最后用处理后的输入生成回答。
4. 查看输入变化、两份回答与搜索记录。由读者标注两份回答是否拒绝或配合原始受限目标；没有自动安全评估器，默认保持“待判断”。修改问题后，旧结果会明确标记。

三个示例分别提供角色扮演、任务伪装与规则重写的“查看教学示意”入口。示意可以离线阅读，不调用模型，不展示耗时或搜索曲线；切换回“运行实验”后只显示本次真实生成结果。受限请求可以用任意方法测试。当前网页的手工模板包含虚构对话续写、虚构角色、问答补全、伪造对话约定与预设承诺；编码方法仍使用实际编码后的问题。

GCG、AutoDAN 和 COLD-Attack 调用 toolkit 的完整优化器。前端不展示 Python 源码、安装命令或源码下载。编码方法展示的文本是模型实际输入，不是实现代码。

## 架构

- `dist/index.html`：实验界面、方法目录与帮助说明。
- `dist/styles.css`：配色、排版、响应式布局。
- `dist/app.js`：方法说明、提交与轮询、输入高亮、搜索轨迹、回答对照。
- `server.py`：HTTP 服务，可加载模型并调用 `src/textbook_toolkit`，或通过回环地址代理远程 API。
- `private/legacy-assets/`：旧展示站生成资产，保留用于恢复，不对网页开放。

服务只提供指定前端文件和三个 API 路由：`GET /api/health`、`POST /api/runs`、`GET /api/runs/<id>`。模型、Python 源码、旧源码快照与压缩包均不属于公开文件。前端 JS/CSS 是浏览器运行必需的资源，不承载优化器实现。

实验一次运行一个，最多在远程服务内存中保留 20 条记录。刷新页面可以接续当前实验；远程服务重启后记录失效。问题经 SSH 隧道发送到用户指定的远程主机，回答由该主机的模型生成。问题与回答不写入访问日志，不调用第三方模型 API。验证脚本显式保存的实验 JSON 则保存在输出目录中。

## 如何理解结果

当前远程运行使用 7B 模型与较少尝试轮数，便于课堂观察，不能据此复现论文级成功率。三种优化器保留真实损失、真实轨迹和实际回答；没有改进时也不会伪造改进。COLD 的曲线是离散解码后文字的目标损失，不是连续优化总能量；最优组合目标与最低目标损失不必对应同一输入。当前远程输出最多生成 128 个词元，较长回答可能被截断；模型名称和输出上限由后台实时报告。

网页展示的是教学推理流程，模型计算发生在用户的远程主机。网站没有外部字体、统计脚本或 CDN 依赖。
