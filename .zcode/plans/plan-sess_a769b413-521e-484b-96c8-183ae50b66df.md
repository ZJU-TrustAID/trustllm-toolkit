# 将 alignment_toolkit 接入 hub（第四章 · 安全对齐）

## Context
仓库是《可信大模型》教材配套工具包集成：`hub/` 通过扫描各工具包目录下的 `chapter.yaml` 自动发现章节（无需改 hub 源码），各章需提供 ①`chapter.yaml` 清单 ②`--config/--output-dir` 形式的 hub_adapter 后端 ③带 `/api/health` 的前端服务（hub 反代嵌入 iframe）。alignment_toolkit（SFT/DPO/RLHF 对齐实验，默认 TRL 后端）已有完整前端 `docs/server.py`（/guide 指南 + /console 训练控制台 + /demo，纯 CSS 变量配色）和 src 包，但缺 hub 接入层。用户已确认：**原地改色**——直接把 docs 前端 CSS 调成 hub 的暖纸底+墨绿色调，布局/HTML/JS 不动。

guardrail 已注册为 chapter 5，故第四章编号 4 可用。前端端口沿用约定取 **8786**。

## 改动文件

### 1. 新建 `alignment_toolkit/chapter.yaml`
仿 `hallucination/chapter.yaml` 结构：
- `chapter: 4`、`title: 安全对齐`、`toolkit: alignment`、brief 描述 SFT/DPO/RLHF 多阶段对齐 + 安全评估
- `frontend`: mode `proxy`、autostart `true`；`server.command: ["{conda}","run","--no-capture-output","-n","alignment-toolkit","python","docs/server.py","--port","{port}"]`（cwd 默认为工具包目录）、`ready_path: /api/health`、`port: 8786`；`config` 模板注入 `model: "{models.base.entry}"` → 经环境变量 `ALIGNMENT_HUB_MODEL` 传入（见第 3 点）
- `backend.command: ["{conda}","run","--no-capture-output","-n","alignment-toolkit","python","-m","alignment_toolkit.hub_adapter","--config","{yaml}","--output-dir","{output_dir}"]`，timeout 3600
- `models`: 单一角色 `base`（基座模型），accepts `[local_path, hf]`，default `{source: hf, repo: Qwen/Qwen2.5-1.5B-Instruct}`
- `params`（带 `when` 条件联动，对齐 docs/server.py `build_training_config` 的字段）：`workflow`(enum sft/dpo/rlhf)、`epochs`、`learning_rate`、`batch_size`、`gradient_accumulation_steps`、`max_length`、`lora`(bool)、`beta`(dpo)、`sft_dataset`/`preference_dataset`/`prompt_dataset`(text, HF id)、RLHF 专属 `ppo_episodes/response_length/kl_coef/ppo_epochs` 等、`evaluate`(bool)+`eval_max_samples`+`eval_profile`、`output_root`
- `results: {primary: report.md, files: [report.md, report.json]}`

### 2. 新建 `alignment_toolkit/src/alignment_toolkit/hub_adapter.py`
hub_adapter 契约（参考 `hallucination/src/hallucination/hub_adapter.py`）：
- 读取 hub 统一 YAML（`version/chapter/toolkit/common/models/chapter_params`），取 `models.base.entry`（用 `trustllm_hub` 无关的本地解析即可，hallucination adapter 自行解析 YAML，照做）
- `build_experiment_config(chapter_params, model_entry, output_dir)`：镜像 docs/server.py 的 `build_training_config` 组装逻辑（workflow→stages、数据集、LoRA/merge、PPO 参数），evaluation 打开时挂 `refusal_heuristic` suites（profile safety_alignment）；输出 root 指向 session output_dir 下子目录，保证产物落在会话目录
- 调 `load_experiment` + `AlignmentExperiment(spec, TRLRunner()).run()`；print(..., flush=True) 进度
- 成功写 `result.json`（status/summary/blocks：markdown 说明 + 各 stage 表格 + 评估指标表 refusal_rate/attack_success_rate/over_refusal_rate）+ `report.md`/`report.json`；失败也写 failed 的 result.json 并 exit 2
- 附带 `--dry-run` 支持（只 resolve 校验，便于无 GPU 冒烟）

### 3. 改 `alignment_toolkit/docs/server.py`（最小改动）
- 读环境变量 `ALIGNMENT_HUB_MODEL`（hub 的 frontend.server env 注入），`/api/health` 返回 `{status, hub_model}`；`console.js` 启动时若 hub_model 存在则预填控制台模型输入框（不改布局）

### 4. 原地改色 `alignment_toolkit/docs/static/{styles,console,demo}.css`
只改 `:root` CSS 变量与散落的硬编码主题色（如 acid 绿 `#b7dc45`、蓝 `#3c5be0`、纸色等）：
- 底色→hub 暖纸系：`--bg/--paper: #f2f0ea`、面板 `#fbfaf6`、边框 `#ddd8cb`
- 主强调色→hub 墨绿：`#0e9f6c`（深 `#0b7a54`、弱底 `#e2f2ea`）、链接/次要蓝 `#2563eb`
- 选择器、布局、HTML、JS 一律不动；逐一 grep 各 CSS/JS 中硬编码色值补齐

### 5. 文档
