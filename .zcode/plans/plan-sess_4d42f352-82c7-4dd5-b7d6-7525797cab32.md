# 将 data-watermark-toolkit 接入 hub（第二章 · 数据集水印）

## Context

hub（`/data2/trustllm/hub`，端口 8680）已接入第三/四·五/六/七章四个工具包，第二章「数据版权保护」仍是"建设中"。`data-watermark-toolkit/` 自带两套系统：纯 Python 模拟器（`toolkit/datamark`）与真实训练实验台（`toolkit/datamark.real` + `toolkit.html` + `toolkit_server.py`），但没有任何 hub 接入代码。

**目标**：新增 chapter.yaml + 章节前端 + hub_adapter，让 hub 总览页出现第二章「数据集水印」。前端风格色调与 hub 统一（暖纸底 `--bg:#f2f0ea`、墨绿黑 `--ink:#1d2a24`、青绿 `--accent:#0e9f6c` 等变量，取自 `hub/src/trustllm_hub/static/styles.css` 的 `:root`），但功能与现有真实训练实验台完全一致。

**已确认的决策**（用户选定）：
- 功能范围：仅**真实训练实验台**（5 方法 GPU 微调实验，与 toolkit.html 功能一一对应；不含模拟器 tab 与演示数据页）
- 环境：新建 conda env `datamark`（torch==2.8.0+cu128 + transformers + peft + tokenizers + pyyaml，按 `toolkit/requirements-deploy.txt`）
- slug：`datamark`，端口 **8785**（端口约定顺延：8781–8784 已占用）

## 接入机制（hub 零改动）

hub 启动时 `config.iter_chapter_dirs()` 自动扫描含 `chapter.yaml` 的根级目录；前端经 `/proxy/datamark/` 同源反代内嵌 iframe；一键执行走统一 YAML → `serve.hub_adapter` 子进程 → `result.json` 契约。参照 `MarkSec/chapter.yaml` + `MarkSec/src/hub_adapter.py` 的模式。

## 新增文件（全部在 data-watermark-toolkit/ 下，不动 toolkit/ 现有代码）

### 1. `chapter.yaml`
- `chapter: 2`、`title: 数据集水印`、`toolkit: datamark`、`enabled: true` + brief
- `frontend.mode: proxy`，`autostart: true`（纯标准库前端服务，模型在实验提交时才加载）
- `server.command`: `["{conda}","run","--no-capture-output","-n","datamark","python","serve/server.py","--config","{config}"]`，`port: 8785`，`ready_path: /api/health`，`config` 模板 `{model: "{models.default.entry}", device: "{common.device}", dtype: "{common.dtype}", seed: "{common.seed}", web: {host: 127.0.0.1}}`，`config_port_key: web.port`
- `backend.command`: `["{conda}","run","--no-capture-output","-n","datamark","python","-m","serve.hub_adapter","--config","{yaml}","--output-dir","{output_dir}"]`，`timeout: 7200`（真实训练较慢）
- `models`: 单角色 `default`（`accepts: [local_path, hf]`，默认 `HuggingFaceTB/SmolLM2-135M-Instruct`，CPU 可跑，与 MarkSec 默认一致；GPU 可换 Qwen3.5）
- `params`（工作台抽屉）: `method`（enum 5 方法）、`fraction`（float 0.5，注入比例 ρ）、`finetune`（enum lora/full）、`epochs`（int 3）、`lr`（float 0.0001）；seed 走顶栏公共参数
- `results`: `primary: report.md`，`files: [report.md, results.json]`

### 2. `serve/` 包（新目录，4 个文件 + tests）
- **`serve/server.py`** — 纯标准库 ThreadingHTTPServer（参照 `toolkit/scripts/toolkit_server.py` 与 guardrail 的 server 模式）：
  - 读 hub 渲染的 `--config` JSON（模型 entry/设备/dtype/seed/web.port），**绑定固定端口不自动顺延**（hub 按端口探活）
  - `GET /api/health`（ready_path，轻量不加载模型）、`GET /` 与 `/static/*`（相对路径资源）
  - 复用实验台 API 面（功能对齐 toolkit_server.py）：`GET /api/meta`（方法列表 family/access/reference/defaults/白名单参数 + 运行环境默认值——默认值取 hub 配置而非 real_qwen35.json 里的 /data3 路径）、`POST /api/run`（单并发 409、依赖预检查、子进程 `python -m datamark.real.cli run`）、`GET /api/job?id=`（状态/log_tail/报告摘要）、`GET /api/job/{id}/report`、`POST /api/stop`
  - 从 `toolkit_server.py` import 复用：`OVERRIDES` 白名单、`child_env`、`check_runtime`；本地实现参数化的 `normalize_runtime`/`build_config`（默认值来自 hub 配置；支持 HF repo id + offline 开关；`token_statistics` 强制 full 微调 + radio 配置规则保持一致）
- **`serve/static/{index.html, styles.css, app.js}`** — hub 风格真实实验台（移植 toolkit.html 的全部逻辑，仅换肤）：
  - 布局：左栏「方法」卡（5 方法 + 中文族名/访问假设/论文引用）与「运行环境」信息卡；右栏预设 chips（强注入 ρ=0.5 / 弱注入 ρ=0.1 / 负对照 ρ=0）、运行环境折叠区（解释器/PYTHONPATH/CUDA/HF_HOME/离线 + 模型目录/设备/dtype/微调方式/LoRA r·α/chat 模板/梯度检查点）、共享参数（ρ/seed）、方法专属参数、开始/停止按钮、指标条、深色日志窗、report.json 展开
  - 保留 toolkit.html 行为：弱预设覆盖参数、`token_statistics` 自动切 full 的提示、2 秒日志轮询、α=1% 判定展示
- **`serve/hub_adapter.py`** — `python -m serve.hub_adapter --config {yaml} --output-dir {output_dir}`（cwd=toolkit 根目录，`-m serve` 可解析）：
  - 读统一 YAML 的 `chapter_params/models/common`；`_entry_string` 拒绝 api 源；严格校验 params（方法枚举、ρ∈[0,1]、finetune 枚举、epochs/lr 范围）
  - 由 models.default + common.device/dtype/seed 构建 datamark.real 配置（模型名/设备/dtype 覆盖），依赖预检（缺 torch → failed result.json 说明），子进程跑 `datamark.real.cli run`（stdout 进 run.log），读 report.json
  - 产出契约同 MarkSec：`report.md`（参数表 + 检测结果表 score/n/p/判定 + 训练摘要）、`results.json`、`result.json`（status/summary/blocks/artifacts）；任何失败写 failed `result.json` 并 exit 2，成功 exit 0

### 3. `serve/tests/`（离线，无 GPU）
