# MarkSec 接入 hub · 第七章「文本水印」

## Context

`hub/` 是各章工具包的统一入口，按设计**接入新章节零改动 hub**：章节目录放 `chapter.yaml`（hub 启动时扫描 `chapter_dirs=["."]` 的直接子目录，MarkSec 不在排除列表，会自动发现）+ 包内实现 `hub_adapter`（`--config`/`--output-dir` → 写 `result.json` 契约）。

用户要求：对应第七章（生成内容溯源），工具包名称为**文本水印**；内置轻量网页**功能与 MarkSec 现有 Next.js 界面一致**；hub 适配器任务范围 = 现有 Web 前端已有的任务（即 live 工具台：水印生成 → LLMP 改写 → 检测，**无独立 detect 任务**）。

已确认的现有 live 界面功能（`webpage/src/components/demo/`）：capabilities 状态条（模型名/提示）→ Prompt 输入（≤4096）→ Watermark 下拉（KGW/Unigram，来自 capabilities）→ Attack 下拉（LLMP）→ Run 按钮（**固定 max_new_tokens=128、seed=42**，与现有一致）→ 结果区：着色开关、两个变体（Watermarked/Attacked）的检测卡片（状态文案 "Insufficient tokens/Watermark Detected/Below threshold"、Z-Score、Green %、Scored、reason）+ 逐 token 绿/红/neutral 着色（verbatim 间距）+ 分数说明。预设 demo 页（固定答案、不调模型）**不移植**——hub 中后端始终真实存在。

## 改动清单

### 1. 新建 `MarkSec/chapter.yaml`

```yaml
# 第七章 · 生成内容溯源 —— hub 接入清单（MarkSec 文本水印）
chapter: 7
title: 文本水印
toolkit: marksec            # slug 仅小写/数字/-/_
enabled: true
brief: MarkSec 文本水印实验台：KGW / Unigram 水印生成、LLMP 改写攻击与 z 分数检测（token 级绿/红着色）。

frontend:
  mode: proxy
  autostart: true           # 服务轻量：模型在首次真实调用时才懒加载
  server:
    command: ["{conda}", "run", "--no-capture-output", "-n", "marksec", "python", "-m", "src.api",
              "--host", "127.0.0.1", "--port", "{port}"]
    port: 8783              # 沿用 hub 端口约定：8781 hallucination / 8782 guardrail
    ready_path: /health     # MarkSec 健康路由是 /health（非 /api/health）
    timeout: 3600
    env:                    # hub 公共模型/设备注入 API 引擎（Settings.from_env 读取）
      MARKSEC_MODEL_ID: "{models.default.entry}"
      MARKSEC_DEVICE: "{common.device}"
  entry: /

backend:
  command: ["{conda}", "run", "--no-capture-output", "-n", "marksec", "python", "-m", "src.hub_adapter",
            "--config", "{yaml}", "--output-dir", "{output_dir}"]
  timeout: 3600

models:
  - role: default
    title: 生成模型（水印嵌入与 LLMP 改写共用）
    accepts: [local_path, hf]        # 不接受 api：水印 logits 生成需本地权重
    required: true
    default: {source: hf, repo: "HuggingFaceTB/SmolLM2-135M-Instruct"}   # CPU 可跑，与 MarkSec 默认一致

params:   # 与现有 Web 界面控件一一对应（现界面固定 128/42）
  - {key: prompt, type: text, default: "Explain what a zero-knowledge proof is and give a simple analogy.", title: 提示词}
  - {key: watermark, type: enum, options: [KGW, Unigram], default: KGW, title: 水印算法}
  - {key: attack, type: enum, options: [LLMP], default: LLMP, title: 攻击方法}
  - {key: max_new_tokens, type: int, default: 128, title: 生成长度上限}
  - {key: seed, type: int, default: 42, title: 随机种子}

results:
  primary: report.md
  files: [report.md, results.json]
```

hub 以 `cwd=章节目录` 启动命令，故 `python -m src.api` / `-m src.hub_adapter` 可直接导入 `src` 包（与 guardrail/hallucination 同机制）。

### 2. 新建 `MarkSec/src/hub_adapter.py`（`python -m src.hub_adapter --config X --output-dir D`）

薄封装，复用现有引擎，不新增水印逻辑：

- CLI/结构仿 `guardrail_toolkit/src/guardrail_toolkit/hub_adapter.py`：`--config`/`--output-dir` 必填、进度用 `print(..., flush=True)`、`_fail(output_dir, msg)` 写失败 `result.json` 并返回退出码 2、顶层 `except Exception` 兜底保证任何崩溃都有 result.json。
- 读 YAML：`common`（device；dtype 说明：引擎固定 fp16-cuda/fp32-cpu，dtype 仅记录进报告）、`models.default`（local_path→绝对路径 / hf→repo；api 来源 → `_fail` 明确报错，仿 guardrail）、`chapter_params`（prompt 必填缺失则 fail；watermark ∈ {KGW,Unigram}；attack ∈ {LLMP}，仅校验预留；max_new_tokens/seed 缺省 128/42）。
- 引擎：`ToolkitEngine(Settings(model_id=<entry>, device=<common.device>))`，直接调 `engine.run(prompt=…, watermark=…, max_new_tokens=…, seed=…)`（签名见 `MarkSec/src/api/engine.py:146`）；`load_engine()` 独立成函数便于测试注入。
- 产出（写入 output-dir）：`result.json`（契约：status/summary/blocks/artifacts/data）、`report.md`（blocks 渲染）、`results.json`（engine 返回的完整 scenario 原始数据）。
- blocks：markdown（实验设置：模型/水印 γ/δ/前缀/seed/设备/耗时，取自 scenario.watermark+provenance）→ table（检测对比，header `["变体","判定","Z 分数","绿 token 占比","计分 token 数","阈值"]`，行 = Watermarked/Attacked）→ markdown（两段文本放代码块，保留空白）→ markdown（结论：LLMP 改写后 z 分数变化与判定）。

### 3. 内置工作台页面（对齐现有 Next.js live 界面）

- 新建 `MarkSec/src/api/static/workbench.html`：单文件原生 HTML/CSS/JS（无构建）。功能与 `WatermarkWorkbench.tsx + DetectionCard.tsx + TokenText.tsx` 一致：capabilities 状态条、Prompt/水印/攻击控件、Run（`{prompt, watermark, attack, max_new_tokens: 128, seed: 42}`，300s 超时）、着色开关、检测卡片（含 reason、阈值内文案）、token 着色（green/red/neutral 背景 + `title="Pos: n | label"`、verbatim 间距）、错误提示与运行中状态。**所有 fetch 用相对路径**（`v1/capabilities`、`v1/run`）——独立部署（`127.0.0.1:8783/`）与 hub 代理（`/proxy/marksec/`）下都正确（hub README 前端契约）。
- 修改 `MarkSec/src/api/app.py`：加 `GET /`（include_in_schema=False）→ `FileResponse` 返回该页面。不改动任何现有路由/鉴权逻辑。

### 4. 新建 `MarkSec/tests/test_hub_adapter.py`（CPU 离线）

仿 `MarkSec/tests/test_toolkit_api.py` 的注入模式：随机初始化 tiny `GPT2LMHeadModel`（vocab 16）+ WordLevel tokenizer → monkeypatch `hub_adapter.load_engine` 返回注入引擎 → tmp 目录写统一 YAML（local_path 指向 "offline-unit-test-model"）→ 调 `main(["--config", …, "--output-dir", …])` 断言：退出码 0、result.json status=succeeded、blocks 含 table、artifacts 含 report.md/results.json、报告文件存在；失败路径：缺 prompt / api 模型来源 → 退出码 2 且 result.json status=failed。

## 验证

1. **清单校验**（hub 环境，离线）：`load_manifest('MarkSec/chapter.yaml')` + 用 `schema.validate_config` 走一份样例运行 YAML（含 models.default/chapter_params）。
2. **适配器单测**（marksec 环境，CPU 离线）：`conda run -n marksec python -m pytest MarkSec/tests/test_hub_adapter.py -q`（tiny 模型注入，不联网）。
3. **环境搭建**：`conda create -n marksec python=3.11`；torch 按 MarkSec README（本机验证先用 CPU wheel 即可跑 135M；GPU 机器装 CUDA wheel）+ `pip install -e 'MarkSec[api,dev]'`。
4. **hub 端到端**：重启 hub → `GET /api/chapters` 出现「文本水印」卡片 → 启动该章交互服务（健康检查 `/health`）→ 经 `/proxy/marksec/` 打开工作台页面跑一次真实 run（默认 SmolLM2-135M，需 HF 网络；不可达时设 `HF_ENDPOINT=https://hf-mirror.com`）→ 抽屉生成 YAML → 执行 → 运行页看到表格/文本结果块并下载 report.md。
