# `datamark.real` 方法实现与论文对应性审计

本文件回答两个问题：**（1）五个方法是否按论文原文实现；（2）当前 demo 的实验机制是否严谨。**
审计对象是 `datamark/real/methods.py`、`experiment.py`、`lm.py`，以及 2026-10 的 demo 数据。

---

## 0. 结论摘要

1. **五个方法都实现了论文的核心协议**（注入方式 + 检测统计量 + 判定逻辑），不是“名字对不上”的模拟。
2. **但注入强度普遍高于论文实验设置**，这是“全部检出”的主要原因：
   - 内容记忆型：同一 trap 在同一文档末尾重复 **5 次**；论文的 trap 重复次数通常为 1 次或很少几次，且会单独报告“重复次数 vs 检出”的消融。
   - 版本对照型：**50% 文档**的正文被整段替换为水印版；论文会报告更低比例。
   - 语义知识型：**16 条**虚构事实（4 实体 × 4 属性），其中一半文档每条都带一条事实；论文用更多事实、更分散的注入。
   - 分布统计型：**96 段**带水印合成文本、δ=2.0、**6 epochs 全参微调**；论文的水印数据量与训练轮数不同。
   - 触发行为型：ρ=0.5 时毒化率 = ρ/(1−ρ) = **50%**；论文的后门注入率通常低一个数量级（1%–10%）。
3. **统计机制上有几处必须说明的简化**（不改变方法对应关系，但影响 p 值解释）：
   - 分布统计型用 99 个控制密钥做置换检验，p 值下限 1/100=0.01；α=1% 时永远不可能显著。**从 2026-11 的边界实验起改为 499 个控制密钥**（下限 0.002）。
   - 内容记忆型/版本对照型/语义知识型都是**小样本**（48 对 / 48 对 / 16 条事实），p 值对样本量敏感。
   - demo 主表每个条件只有 **2 个 seed**；证据页只展示 1 次实验。
   - 五个方法各做多次检验，**没有做多重比较校正**；教科书里应说明这是演示而非确证性实验。
4. **已修复的严谨性问题**：ρ=0 负对照的空样本处理（避免除零/空检验）、分布统计型在 ρ=0 时仍能给出合法 p 值、置换检验分辨率、弱注入与负对照两组实验。

## 1. 逐方法对应表

### 1.1 内容记忆型 — Copyright Traps（Meeus et al., ICML 2024）

| 论文要素 | 本实现 | 对应性 |
|---|---|---|
| 在训练文档中插入独特 trap 序列 | 对选中文档，在**原文末尾**追加 16-token 的合成 trap | ✅ 核心一致（位置简化为末尾） |
| trap 可重复 R 次以增强记忆 | `repeats=5`（强设置）；弱设置为 1 | ✅ 机制一致，**强度偏高** |
| 非成员对照 trap 用同样方式生成但不入训练集 | ✅ 每个成员 trap 配一条同流程生成的控制 trap | ✅ |
| 检测：成员/非成员 trap 的 loss 差异（MIA） | 单条 trap 的平均 NLL，单侧 Welch t + AUC | ✅ 论文用 loss/AUC，t 检验是等价统计表述 |
| trap 形态 | 由基座模型采样的短句（Qwen3.5-4B 后通顺） | ⚠️ 论文可用随机序列/虚构句；我们的是模型生成自然句，可能更易记忆 |

**偏差影响**：末尾追加 + 重复 5 次会显著放大成员信号；弱注入实验（repeats=1、ρ=0.1）用来量化这一点。

### 1.2 版本对照型 — STAMP（Rastogi et al., ICML 2025）

| 论文要素 | 本实现 | 对应性 |
|---|---|---|
| 对文档生成多个 KGW 水印改写，公开一个、保留其余 | 每文档生成 1 个 public + 1 个 private（不同密钥） | ⚠️ 私有版本数从“多个”简化为 1 个（已在 README 说明） |
| 可疑模型在公开版上微调 | ✅ 选中文档的正文替换为 public 改写后做 SFT | ✅ |
| 检测：public 与 private 的 perplexity 差异 | 配对单侧 t 检验，`PPL(public) − PPL(private) < 0`；先按论文做 5% 截尾 | ✅ |
| 水印生成 | KGW 哈希绿名单 + δ=1.5 | ✅（哈希划分与随机划分同分布，见 kgw.py 说明） |
| 改写质量 | Qwen3.5-4B 生成，中文可读 | ✅（换 4B 后明显改善） |

**偏差影响**：只有 1 个 private 版本，检测方差比论文大；论文的“多版本平均”会降低方差。ρ=0.5 时一半文档被整段替换，强度偏高。

### 1.3 语义知识型 — Fictitious Knowledge（Cui et al., ACL 2025 Findings）

| 论文要素 | 本实现 | 对应性 |
|---|---|---|
| 构造虚构实体/属性/取值 | 4 实体 × 4 属性 = 16 条事实，取值由密钥哈希确定 | ✅ |
| 把事实写进训练 passage | 让基座模型扩写；若生成段落未包含事实句则**强制前置补齐** | ⚠️ 强制补齐保证注入成功，但比论文“自然改写”更强 |
| 可疑模型在含事实的语料上微调 | ✅ 选中文档追加 passage | ✅ |
| 检测：正确属性 vs 控制属性的条件似然 | 事实前缀补全（“X 的 Y 为___”）+ 配对单侧 t；另附 3 种问法的命中矩阵 | ✅ 论文用 QA/事实似然，统计形式一致 |
| 规模 | 16 条事实；ρ=0.5 时约 3 条文档/事实 | ⚠️ 论文用数千条事实，小样本 p 值不稳 |

**偏差影响**：事实数少、每条事实重复出现，模型更容易记住；ρ=0.25 时已出现 p≈0.01 的边缘显著，说明信号偏强。

### 1.4 分布统计型 — Radioactive（Sander et al., NeurIPS 2024）

| 论文要素 | 本实现 | 对应性 |
|---|---|---|
| 用 KGW 水印生成合成训练数据 | 40/96 段（按配置）带 δ 的生成文本 | ✅ |
| 模型在“水印 + 干净”混合数据上微调 | 按 ρ 反推干净文本数，保持水印文本占比 = ρ | ✅ |
| 检测：可疑模型生成文本中真实密钥的 green token 是否多于控制密钥 | 40 条提示 × 60 token，真实密钥 vs 499 控制密钥的置换检验 | ✅ 核心一致 |
| 水印机制 | 哈希版 KGW（与随机划分等价） | ✅ |
| 训练方式 | **全参微调 + 8-bit Adam**（LoRA 学不动 green 偏好，已实测 p≈0.1） | ✅ 与论文全参微调一致；LoRA 不适用已记录 |
| 置换检验分辨率 | 旧数据 99 个控制密钥（p 下限 0.01）；新实验 499 个 | ⚠️ 旧 demo 数据在 α=1% 下不可判 |
| 数据规模/轮数 | 96 段 × 6 epochs（强）；弱设置 16 段 × 3 epochs | ⚠️ 强设置偏高 |

**偏差影响**：强设置下 ρ=1 的 p 值只是“≤0.01”，不能当作精确 p；新实验已提高分辨率。

### 1.5 触发行为型 — Double-I（Li et al., arXiv 2402.14883）

| 论文要素 | 本实现 | 对应性 |
|---|---|---|
| instruction 触发 + input 触发 | 指令前加“青禾【编号校验】”，输入末尾加“青禾”，两类同时使用 | ✅（论文 3.3.3 讨论过多触发混用） |
| 毒化样本把标签翻转为相反答案 | ✅ 对 clean 样本翻转“是/否” | ✅ |
| SFT 只在答案部分计 loss | ✅ `train_completion`（prompt 部分 mask） | ✅ 后门标签只有 1 token，必须这样训 |
| 检测：trigger set vs reference set 的操纵率 | 16 条 reference + 32 条 trigger，单侧 Fisher 精确检验 + odds ratio | ✅ 论文用 Fisher 检验 |
| 毒化比例 | ρ=0.5 → **50%** 毒化；论文通常 1%–10% | ⚠️ **强度显著偏高** |
| 触发词 | 固定“青禾”+ 装饰串 | ✅ 机制一致 |

**偏差影响**：50% 毒化率下 Fisher p=4e-13 是“必然检出”；弱注入实验把 ρ 降到 0.1（毒化率约 11%）。

## 1.6 审计中发现并修复的问题

审计不是走过场，实际发现了 3 个会影响结论的问题，均已修复并重跑相关实验：

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | **Double-I 训练/验证泄漏**：验证文档 `docs[:16]` 恰好也是投毒样本的前 16 条，检测实际上是在“训练集上考后门” | 主表 ρ=0.5 与弱注入 ρ=0.1 都出现完全操纵（32/32，p=4.4e-13），p 值与注入率无关，明显异常 | 验证集改为 `docs[-16:]` 的 held-out 文档，投毒只从其余文档抽取；manifest 记录 `n_verify` |
| 2 | **分布统计型置换检验分辨率不足**：99 个控制密钥使 p 值下限为 0.01 | ρ=1.0 时 p=0.01，α=1% 下永远“未检出”，是分辨率假象 | 新实验改为 499 个控制密钥（p 下限 0.002）；旧数据保留但明确标注 |
| 3 | **ρ=0 负对照的边界处理**：分布统计型在 ρ=0 时按 `(1-ρ)/ρ` 反推干净文本会除零；无评分 token 时也不应返回 p=0.01 | 负对照无法运行 / 可能误报 | ρ=0 分支训练集全干净；空样本返回 p=1.0；新增 `clean_texts`、`max_clean_texts`、`detect_prompts` 配置 |
| 4 | **分布统计型逐文档去重导致 p 值失真**：模板化生成文本中相同 n-gram 在 96 段里反复出现，逐文档去重后控制密钥的 green 计数方差被放大（sd≈170 vs 二项 sd≈32），p 值失去分辨力，强注入 ρ=0.5 也只有 p=0.1 | “分布统计型全部检不出”是统计量问题，不是方法失效 | 改为**跨文档全局 (k+1)-gram 去重**（有效 n 从“重复计数”变为独立 n-gram 数），并用 499 个控制密钥置换；同一批生成文本离线重算，不重跑模型。修正后 ρ=0.25/0.5/1.0 分别 p=0.01/0.002/0.002 |
| 5 | **负对照的误报复核**：内容记忆型 ρ=0 的 seed42 p=0.0418、分布统计型 seed42 p=0.048 | 看起来像“干净数据也检出”，实际是 α=5% 名义误报；demo 已把判定边界收紧到 α=1%，这两个点不再判为检出 | 核验训练文本无 trap 泄漏、trap/对照同流程生成；内容记忆型补测 10 个负对照 seed，仅 seed42 一次 p<0.05（1/10），与名义 5% 一致；页面在负对照条件给出提示 |

## 3. 结论与建议

- **“全部检出”不是检测器太强，而是注入条件太强。** 主表 ρ=0.5、repeats=5、整段改写、50% 毒化，属于“教学上先看到信号”的强设置。
- 新增两组实验用于给出**边界与负对照**（2026-11 实测，Qwen3.5-4B，各 2 seeds）：

| 方法 | 弱注入 ρ=0.1 | 负对照 ρ=0（干净） |
|---|---|---|
| 内容记忆型 | **1/2 检出**（p=0.011 / 0.082） | 1/10 检出（仅 seed42 p=0.042；补测 8 个 seed 均 >0.05） |
| 版本对照型 | **2/2 检出**（p=5.5e-5 / 5.5e-5） | 0/2 检出（p=0.518 / 0.229） |
| 语义知识型 | 0/2 检出（p=0.336 / 0.364） | 0/2 检出（p=0.473 / 0.521） |
| 分布统计型 | 0/2 检出（p=0.16 / 0.774） | 1/2 检出（p=0.048 / 0.58；名义误报） |
| 触发行为型 | **1/2 检出**（p=1.0 / 4.4e-13） | 0/2 检出（p=1.0 / 1.0） |

  解读：
  1. **弱注入下 5 个方法里有 2 个明显失去检测力**（语义知识、分布统计），内容记忆型降到边缘，触发行为型变得不稳定——证明主表的“全部检出”主要来自强注入。
  2. **负对照基本干净**：4 个方法 0/2 误报；内容记忆型 1/2（p=0.042）是名义 5% 水平下的正常误报，但也说明 **2 个 seed 不足以估计 FPR**，教材里不能把它当作“无误报”的证据。
  3. **版本对照型在 ρ=0.1 仍稳定检出**：它的检测是逐文档成员检验，10 对文档的 PPL 差异已经足够大；这不代表注入弱，而是该统计量对“整段改写”非常敏感。
  4. **Double-I 的检出率与毒化率强相关**：ρ=0.1（毒化率约 11%）时 1/2 检出，ρ≥0.25 时 2/2 完全操纵——后门需要足够多的投毒样本。
  5. **修复训练/验证泄漏后，主表高 ρ 结论不变**（held-out 验证仍 32/32 对 0/16），说明高毒化率下 trigger 是全局特征，不是记住训练样本；但弱毒化率下不能外推。
- 教材/答辩表述建议：
  1. 明确主表是“强注入、验证方法可实现”，不是“方法在真实条件下的检出率”；
  2. 用弱注入与负对照两张表说明**检出随注入强度变化**；
  3. 说明 p 值下限与样本量限制，避免把 p=0.01 解释成精确值；
  4. 多重比较与攻击鲁棒性作为“未覆盖”明确列出。
